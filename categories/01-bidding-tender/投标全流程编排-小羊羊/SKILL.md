# 投标全流程编排器（小羊羊AI体系）

> 本技能是**投标技术方案编写的入口与总指挥**。它本身不写正文，而是确保标准四步法（提取→监督→编写→排版）被严格按顺序执行，并在需要时衔接废标审查与审批信息整理。

---

## 一、核心铁律（不可违背）

1. **严禁跳步**：未产出 `bidding_profile.json` 之前，禁止进入任何编写环节。
2. **监督前置**：进入编写技能之前，必须先加载「技术方案编写监督--小羊羊AI」，由它在每个 Phase 强制拦截检查。
3. **逐字合规**：一级/二级标题必须从评分标准**逐字提取**，不得加字/减字/换字。
4. **三零原则**：零自创数值、零自创标准、零自创英文（方案中所有数字/标准/英文缩写必须在招标文件中有出处）。
5. **数据驱动字数**：按「单项分值 / 主观分总分 × 目标总字数」分配，总完成率须 95%~105%。

## 三、4 个必须的用户确认节点（来自监督技能）

编写过程中有 4 个节点需要用户确认，其余全自动：
1. **① 目标字数**（Phase 0）— 请用户确认总字数或"默认"。
2. **② 包/标段**（Phase 0.5）— 多包/多标项时确认目标包。
3. **③ 目录 & 篇幅**（Phase 2.6）— 确认目录结构与字数分配。
4. **④ 首章风格方向**（Phase 3A.2）— 审阅第一章后回复"继续"即进入全自动冲刺，不再打断。

## 四、环境依赖（首次使用前安装）

编写/排版/审查脚本依赖以下 Python 库（在 WorkBuddy 受管 Python 中安装）：

```bash
pip install python-docx reportlab markitdown Pillow
```

- `.doc` 旧格式转换、DOCX 转 PDF 需要 **LibreOffice** 或 **MS Word**（Windows COM）。
- 图片 OCR 废标审查需要本地 OCR 能力（可复用 hybrid-image-ocr 的 RapidOCR，或 markitdown 的图片解析）。

---

## 五、与旧投标技能的关系

本编排体系取代旧的通用投标技能（`bid-doc` / `bidwriter` / `bid-writer-pro` / `tender-writer`）用于**技术方案主观分编写**场景——旧技能缺少"关键信息提取产物 + 强制监督闸门 + 逐字标题 + 三零原则 + 质量门"等机制，容易产出拼凑式内容。

若用户只是要"按模板快速生成一份 Word 框架"，旧技能仍可用；但若追求**高得分率、合规、不废标**的正式投标技术方案，一律走本编排链路。

---

## 六、异常处理

若任一子技能执行失败或产物缺失：
- 回到对应 Step 重跑，不得带着缺失产物进入下一环节；
- 在交付汇总中披露「一致性告警」，不掩盖问题。
