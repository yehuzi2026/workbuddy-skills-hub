# 货物类技术方案 — 编写原则（24条）

**Step 3.3 — 编写原则**

1. **逐点响应**：每个三级标题的内容必须与评分标准中的要求点建立可追溯的对应关系
2. **技术底座**：所有方案内容必须以Phase 1中提取的技术参数为约束条件，不得脱离实际设备能力
3. **避免空话**：禁止使用「我们将提供优质服务」「确保项目顺利实施」等无实质内容的表述
4. **数据支撑**：能用数据说明的必须用数据（设备数量、响应时间、人员配置、检测指标等）
5. **法规引用**：涉及合规性要求时，必须引用具体法条（见下方"法律法规模块"中的法规列表）
6. **去AI味编写**（强制）：在编写过程中，必须遵守以下写作纪律，从源头减少AI味：
   - **禁止三连段等长**：同一小节内不得连续3段以上字数相近（差值<20字）的段落
   - **禁止"首先其次最后"连续使用**：将递进信号分散到不同段落，或替换为自然过渡
   - **禁止"我们将"连续开头**：同一小节内"我们将"开头的句子不超过2句
   - **用具体物名替代抽象词**：不说"完善的管理机制"，说"备件箱常备12类易损件"
   - **用数字替代承诺**：不说"快速响应"，说"2小时内到达现场"
   - **用场景替代模板**：不说"建立应急预案"，说"停电后UPS供电30秒内自动切换"
   - **引用招标文件原话作为锚点**：每节至少1次引用招标文件的原文（使用引号标注），增加"人写的"痕迹
7. **以招标文件为蓝本**（强制）：在编写技术、商务或服务类要求时，必须以招标文件的「技术要求」「采购需求」或「服务需求」原文为蓝本，不得脱离招标文件自行想象。每条方案措施的提出，必须有对应的招标文件条款作为依据。
8. **前后内容交叉验证**（强制）：关于同一项内容的表述，必须在全文所有出现位置保持一致，禁止前后矛盾。例如：设备总数在1.3节写206台，在2.2节巡检计划中也必须是206台；响应时限在2.3节写2h/48h，在1.3节应急预案中也必须是2h/48h。
9. **内容质量三要素**（强制）：
   - **关联性与逻辑性**：各要点内容之间关联性要强，逻辑清晰合理。方案不是观点堆砌，是一环扣一环的论证链
   - **完整性与可行性**：结构完整、周全细致，结合现有客观实际情况和项目特征，确保可行性强、能有效实施
   - **实用性**：每项措施对采购人有明确的实际用处，不是泛泛而谈的理论
10. **项目特征深度锚定**（强制）：每个一级标题下的内容中，必须出现**至少3处**本项目的具体特征——不得写泛型方案。特征来源为 Phase 1 提取的设备清单、技术参数、商务条件、楼栋地点等数据。例如设备总量、安装点位名称、核心设备参数、工期要求、质保年限等。方案中用到的具体特征必须与 `bidding_profile.json` 或 `phase0_whitelist.json` 中的数据完全一致。
11. **管理理念先进性**（强制）：方案中必须体现至少**3种**可被评委识别为先进的管理方法：
    - 数字化管理（云平台、IoT监控、工单系统、数据驾驶舱）
    - 闭环改进管理（计划—执行—检查—改进的持续优化循环）
    - 标准化作业流程（将常规作业拆解为可复制、可考核的步骤化规范）
    - 数据驱动决策（故障率分析→预防性维护→设备更新）
    - 精益运营（最小化设备空档期、最大化使用率）
12. **禁止显式蓝本声明**（强制）：禁止在方案正文中写出"本方案以竞争性磋商文件第三章采购内容及要求为蓝本"之类的句子。方案应自然体现对招标文件的理解，而非口头声明。
13. **禁止官方腔调**（强制）：禁止写出"作为竞争性磋商文件明确要求的专门面向中小企业的采购项目"等过于官方/模板化的表述。用日常自然的语言描述项目背景。
14. **禁止招标文件章节引用**（强制）：方案正文中禁止出现以下话术："根据招标文件第五章""评分标准将...列为""招标文件第X章要求""该承诺与招标文件商务要求第X条完全一致""满足招标文件★条款CXX的要求"等。方案应自然体现对招标要求的响应，而非逐条"对答案"。具体要求直接用自然语言陈述即可，无需标注出处。
15. **禁止非招标文件固有的英文单词——单一来源原则（v2.12.0 强化，强制）**

    **铁律：方案正文中出现的任何英文单词（含缩写、全称、品牌名、标准编号中的拉丁字母部分），必须且仅能在招标文件中找到。招标文件中没有的英文单词，一律不得出现。**

    **判定流程（每次写作前执行）：**
    ```
    Step A：扫描招标文件全文 → 提取所有英文单词 → 生成「招标文件英文白名单」
    Step B：方案写作时，每出现一个英文单词 → 查白名单
      ├── 在白名单中 → ✅ 允许
      └── 不在白名单中 → ❌ 立即替换为中文
    ```

    **这意味着 v2.11.0 的「三源」被废除——以下不再自动合法，必须在对应项目的招标文件中逐项核实：**
    - GB、GB/T、JJF、JJG 等标准编号 → 只有招标文件中引用了才允许
    - NMPA、NIFDC、CNAS 等官方缩写 → 只有招标文件中出现了才允许
    - ISO、ISTA、WHO、IATA 等国际标准缩写 → 只有招标文件中出现了才允许

    **常见自创英文替换对照表（招标文件无对应英文时使用）：**

    | 类别 | 英文（禁止） | 替换为中文 |
    |------|------------|-----------|
    | 管理缩写 | CAPA、PDCA、RCA、SOP、KPI、VOC、TCO、AQL、FAQ、FIFO、FTA | 纠正与预防措施、计划—执行—检查—改进循环、根因分析、标准化作业流程、绩效指标、客户声音、全生命周期成本、合格质量水平、常见问题、先进先出、故障树分析 |
    | 品牌名 | Fluke、Kingston、Samsung、Wireshark、ProSim、TeamViewer、Torx | 数字万用表/心电模拟器、专用U盘、网络封包分析工具、远程桌面工具、星形 |
    | 系统/软件 | Windows、Linux、BitLocker、LUKS | 操作系统、磁盘加密 |
    | 技术缩写 | IoT、WiFi/Wi-Fi、GPS、PACS、RIS、HIS、mAh、LED、LCD | 物联网、无线网络、卫星定位、影像归档与通信系统、放射信息系统、医院信息系统、毫安时、发光二极管、液晶显示屏 |
    | 英文全称 | Corrective Action、Preventive Action、Root Cause、Quality Baseline、Total Cost of Ownership | 纠正措施、预防措施、根因、质量基线、全生命周期成本 |
    | 标准/机构 | ISO、NMPA、NIFDC、ISTA、WHO、GDP、IATA、NIST | 质量管理体系/国家药品监督管理局/食品药品检定研究院/国际安全运输协会/世界卫生组织/药品良好分销规范/国际航空运输协会/数据擦除安全标准 |
    | 自创编号 | SOP-SVC-001、Level 1/2/3、MMDD-XXX | 直接用操作规程中文名、第一级/第二级/第三级、填实日期 |

    **判定标准：**
    - 招标文件中不存在的英文 → **P0 错误，立即替换为中文**
    - 替换后必须保证语句语义通顺
    - 不得因"技术术语本该用英文"为由保留——中文方案用中文写，招标文件里有英文的照抄，没有的中文化
16. **标题不含评分信息**（强制）：一级标题、二级标题的正文中不得出现"评分关键词""评分项"等提示评委的信息。评分对应关系由评委自行核对，不在方案中标注。
17. **减少非招标要求的参数值**（强制）：方案正文中出现的所有具体数值（空间尺寸、间距、电阻值、百分比、数量、速率、时间间隔等），必须原封不动来源于招标文件的技术参数或商务条款。禁止自行添加招标文件中未出现的任何具体数值。若方案中需要使用数值来说明观点，有以下替代方式：（1）用定性描述替代定量数值（如"面积满足需求"替代"面积≥8㎡"）；（2）引用招标文件原文（逐字照抄且加引号标注）；（3）引用公开的行业标准或法规中的数值。违反本条导致评委质疑数值来源的，相关段落视为缺陷内容。
18. **人称统一规则**（强制）：全文统一使用"我方""我公司"指代投标人，禁止使用"成交人""中标人""供应商"等第三人称称呼。在合同条款引用等特殊场景下，可保留原文称谓，但描述自身行为时必须用"我方"。
19. **禁止虚构案例数据（强制）**：方案中出现的所有具体项目名称、医院名称、客户名称、项目年份、项目规模、具体成效数据，**必须来源于用户提供的真实信息或招标文件本身**。禁止使用"我公司在XX市XX医院完成的XX项目""2022年绵阳项目""2023年德阳项目"等虚构的案例来佐证观点。如用户未提供真实案例，方案中的论据只能来源于招标文件条款、设备技术原理和行业标准。违反本条视同提供虚假材料，方案中相关段落在交付前必须全部清除。

20. **序号层级递进完整（强制）**：正文中所有带编号的段落，其下属的并列子项必须使用下一级编号。四级序号体系为：一级段落用"1. 2. 3."，其子项用"（1）（2）（3）"，再子项用"1）2）3）"。当一个编号段落下有 2 个及以上并列子点时，子点不得以无编号的裸段落形式出现。例如"1. 安装场地勘察"下面有"空间核查""供电核查""网络核查""时序规划"四个子点，则必须写为"（1）空间核查""（2）供电核查""（3）网络核查""（4）时序规划"。违反本条视同序号层级缺失。

21. **标点符号全部采用中文全角格式（强制，v2.37.0 新增）**：方案正文中所有标点符号必须使用中文全角格式，禁止出现任何半角英文标点符号。

    **全角标点对照表：**

    | 用途 | 半角（禁止） | Unicode | 全角中文（必须） | Unicode |

    | 句号 | `.` | U+002E | `。` | U+3002 |

    | 分号 | `;` | U+003B | `；` | U+FF1B |

    | 左括号 | `(` | U+0028 | `（` | U+FF08 |
    | 右括号 | `)` | U+0029 | `）` | U+FF09 |

    **适用范围：** 此规则适用于方案正文的所有文本位置——标题、正文段落、表格单元格、图片标题、页眉页脚——无一例外。

    **豁免（以下情况半角标点合法）：**
    - 招标文件中原文引用的英文技术参数编号中的标点（如 `USB 3.0`、`HDMI 2.1` 中的小数点）
    - URL 中的标点符号
    - 纯数字表达中的小数点（如 `3.14`）

    **执行方式：** Phase 3 写作时自检（质量门2第2条）→ Phase 4A.5 全文自动扫描验证。违反本条视同格式不规范，Phase 4A 校验不通过。

22. **项目背景深度锚定（v2.39.0 新增，强制）**：每个 H2 章节必须体现对本项目**具体临床场景、科室痛点、地理环境**的深度理解——不仅仅是提到设备名称，而是让读者感觉到"写出这段话的人真的到过广元市利州区中医医院康复科和急诊科"。

    **执行标准——每个 H2 必须包含以下三类锚定中的至少两类：**

    **(a) 临床场景锚定**（描述设备在本科室的实际使用方式）：
    - ❌ 泛泛写法："我方将确保设备满足临床使用需求"
    - ✅ 场景锚定："腰椎牵引器安装于康复科治疗室，每日接诊约15-20名腰椎间盘突出患者，牵引治疗需与PT床训练、理疗等形成治疗链。我方将在安装时配合科室治疗排班表，安排在非高峰时段（下午2点后）进行设备调试，避免中断患者治疗流程。"

    **(b) 科室痛点锚定**（回应科室面临的实际困难）：
    - ❌ 泛泛写法："我方提供设备操作培训"
    - ✅ 痛点锚定："康复科现有腰椎牵引器已使用超8年，医护人员反馈旧设备牵引力控制精度不足（±5kg），常需手动微调。我方提供的腰椎牵引器精度达±0.5kg，培训重点将放在数字化治疗方案存储功能上——减轻医护人员每次重复调参的负担。"

    **(c) 地理环境锚定**（结合医院地理位置和交通条件）：
    - ❌ 泛泛写法："我方确保及时响应"
    - ✅ 地理锚定："医院位于宝轮镇，距广元市中心约15公里。我方在广元服务站点常驻1名服务工程师，到达医院的路程时间约20分钟（经G5京昆高速），确保非高峰时段30分钟内到场。"

    **各 H2 类型推荐的锚定方式：**

    | H2 类型 | 优先锚定方式 | 示例锚定点 |
    |---------|------------|-----------|
    | 安装调试 | 临床场景 + 地理环境 | 治疗排班表、安装楼层、通道尺寸 |
    | 供货配送 | 地理环境 | 厂家分布、运输路线、到院时间 |
    | 质量管控 | 科室痛点 | 旧设备问题、新设备特检重点 |
    | 培训方案 | 科室痛点 + 临床场景 | 医护人员现有水平、培训时段安排 |
    | 技术保障 | 科室痛点 | 设备易发故障、备件需求预测 |
    | 售后服务 | 地理环境 + 科室痛点 | 服务站点位置、常驻人员配置 |
    | 应急保障 | 临床场景 + 地理环境 | 急诊科24小时运转、备用设备调配 |

    **验证方法：** Phase 4A 新增 Step 4A.6"项目锚定覆盖扫描"——逐 H2 检查是否满足"至少两类锚定"要求，未满足 → Phase 4A 不通过。

23. **人类写作自然度（v2.39.0 新增，强制）**：方案读起来必须像一个经验丰富的项目经理在向同事介绍实施方案——专业但易懂、有逻辑但不僵硬、有细节但不啰嗦。

    **(a) 禁止刻意强调（已在核心纪律⑦中加强）**：
    - ❌ 禁用："特别值得一提的是""尤为重要的是""需要特别强调的是""值得关注的是""值得一提的是"
    - 理由：好内容不需要标签提醒读者"这里很重要"。如果内容本身有分量，读者自会感知。

    **(b) 禁止自我评价式表述（已在核心纪律⑦中加强）**：
    - ❌ 禁用："我方方案具有显著优势""本方案优于行业平均水平""这一措施将极大提升""充分体现了""完美诠释了"
    - 理由：方案是承诺书，不是广告文案。承诺用事实和数据说，不需要自己夸自己。

    **(c) 语言节奏自然化**：
    - 段落长短错落：不得连续 3 段以上段落长度相近（差值 < 30 字）
    - 句式多样化：描述性句子和指令性句子交错使用，不得连续 5 句以上使用同一句式
    - "我们将""我方将"在一段内使用不超过 2 次
    - 适当使用短句打断长叙述（如"以上为硬件层面。软件层面同样重要。"）

    **(d) 专业但不故作高深**：
    - 用行业通用术语，但不用生僻词
    - 技术原理说得让非专业人员也能大致理解（评审专家不一定是设备操作者）
    - 比如："牵引力控制采用闭环反馈算法" → 应该说 "牵引力通过传感器实时监测，系统自动微调保持设定的力度不变"

    **(e) 不重复描述**（配合核心纪律⑨）：
    - 已在前面章节充分展开的概念，后续章节不再赘述
    - 如需引用前面的内容，用"如 2.1 节所述"一笔带过，不重新展开
    - 同一三级标题下，不得用不同措辞重复同一观点 2 次以上

24. **真实履约心态（v2.39.0 新增，强制）**：以中标后必须逐条执行方案内容的心态来写作。方案的每一句话都是一个承诺，承诺必须能兑现。

    **(a) 写得出就做得到**：
    - 每写一条操作措施，心里问自己："这条措施，我方的项目经理拿到方案后知道怎么执行吗？"
    - 如果一条措施描述模糊到"反正是要做的但不知道怎么开始"→ 重写，补充具体执行步骤和资源配置
    - 举例："我方将建立完善的备件管理体系" → 到底怎么建？→ 改为："我方将在广元服务站点配置标准化备件柜（长1.2m×宽0.6m×高1.8m），按设备类型分5层存放，每层标注备件编码和最低库存线。系统自动监控库存，低于最低线时触发采购申请。"

    **(b) 量化承诺必须有依据**：
    - 响应时间、人员数量、备件库存、培训课时等具体数字，必须来源三选一：招标文件明确要求 / 设备厂家标准服务协议 / 行业强制规范
    - 禁止凭空编造数字来"显得方案很具体"
    - 举例："我方承诺故障修复时间不超过 4 小时" → 这个 4 小时从哪来的？如果招标文件未要求、厂家未承诺 → 改为"我方承诺第一时间启动故障诊断，根据故障等级确定修复方案和时限，并将预计修复时间及时通报医院设备管理部门"

    **(c) 禁止绝对化承诺**：
    - ❌ 禁用："确保零故障""绝对安全""万无一失""100% 满意""彻底解决"
    - ✅ 替换："目标将年故障率控制在 2% 以下""通过以下五重安全保障措施降低安全风险""建立满意度回访机制，持续改进服务质量"
    - 理由：设备总会出故障，安全总是相对的。绝对化承诺在评标时反而会引起专家质疑。

    **(d) 资质与能力匹配**：
    - 方案中需要特殊资质、许可证或认证才能执行的承诺（如放射设备维保需辐射安全许可证、压力容器安装需特种设备资质等），必须确认我方已持有或可合法获取
    - 如我方不具有且无法获取 → 不得写入方案
    - 如我方通过外包/合作方式可实现 → 方案中应注明"我方委托具备XX资质的合作方执行"，不可隐瞒外包事实

    **(e) 履约自问清单**（质量门8同款，逐节执行）：
    ```
    □ 本节所有量化承诺，我是否能说清数字来源？
    □ 本节所有操作措施，我方执行起来是否有人员/设备/时间上的实际困难？
    □ 本节是否有需要第三方配合的承诺？→ 第三方是否已确认配合？
    □ 本节是否有绝对化表述需要替换？
    □ 本节是否有我方不具备资质的能力承诺需要移除？
    ```
