### 🔴 遗漏9：DOCX 字体/字号/颜色规范被跳过（⚠️ 阿云反馈）
- **发现日期**：2026-05-29
- **问题描述**：MD 转 DOCX 后，正文字体不是宋体、字号不是小四12pt、颜色不是黑色。H1/H2/H3 的字体/字号/加粗规则未逐一验证。
- **后果**：最终交付的 DOCX 字体混乱（默认等线/Calibri 覆盖了宋体设置），在不同电脑/不同 Word 版本上打开排版错乱。这是投标文件的门面问题——字体不统一直接扣印象分。
- **根因**：`doc.add_heading()` 绑定了 Word 内置样式（等线/Calibri），run 级字体设置被样式覆盖。必须改用手动构造段落 + `eastAsia` 锁定宋体。
- **强制验证项**（每次 DOCX 生成后逐项检查）：
  - 正文：宋体、小四12pt、黑色、首行缩进0.74cm
  - H1：宋体、四号14pt、黑色、加粗
  - H2：宋体、四号14pt、黑色、不加粗
  - H3：宋体、小四12pt、黑色、不加粗
  - 表格文字：宋体、五号10.5pt、黑色
  - 图片标题：宋体、小五9pt、黑色
- **本次是否检查**：待填写

### 🔴 遗漏11：图片插入规则三项全部被跳过（⚠️ 阿云反馈）
- **发现日期**：2026-05-29
- **问题描述**：图片插入的三条强制规则在实际执行中被跳过——
  - 规则① **段落中间优先**：图片应嵌在三级标题首段正文之后（H3 → 正文段落 → 图片+标题 → 后续正文），实际被插在了标题正下方
  - 规则② **禁止标题下方直接插图**：图片上方紧邻 `##` 或 `###` 标题、下方才开始写正文 → 违规
  - 规则③ **禁止 Markdown `![]()` 语法**：图片插入必须使用 `python-docx` 的 `add_picture()`，不得在 Markdown 中嵌入 `![]()` 引用。Markdown 中的 `![]()` 行必须在转换前全部删除。
- **后果**：图片位置突兀（卡在标题和正文之间），影响阅读流畅性；`![]()` 语法残留导致 DOCX 中出现无法渲染的标记文字。正式投标文件中此类格式问题属于低级错误。
- **强制验证项**（每次图片插入后逐图检查）：
  - 每张图片上方是否有一段正文（不是标题）？
  - 每张图片下方是否有一段正文（不是标题）？
  - 文档中是否存在残留的 `![]()` 或 Markdown 图片语法？
- **本次是否检查**：待填写

### 🔴 遗漏12：正文序号样式体系混乱（⚠️ 阿云反馈）
- **发现日期**：2026-05-29
- **问题描述**：文档中序号层级不统一、混用序号样式。一级用了阿拉伯数字、二级用了中文数字、三级无编号裸写，或不同章节的序号体系不一致。
- **强制规范（必须逐级验证）**：
  | 层级 | 正确格式 | 错误示例 |
  |------|---------|---------|
  | 一级序号 | 一、二、三、四... | ❌ 1. 第一章 或 一. |
  | 二级序号 | 1. 2. 3. 4... | ❌ (1) (2) 或 一） |
  | 三级序号 | （1）（2）（3）（4）... | ❌ 1） 或 a. |
  | 四级序号 | 1）2）3）4）... | ❌ ● ◆ ▪ 等符号 |
- **禁止使用**：英文字母（a.b.c.）、罗马数字（i.ii.iii.）、项目符号（●◆▪）替代序号
- **后果**：序号体系混乱是投标文件的大忌——评委翻看时无法追踪逻辑层次，直接影响技术方案的"规范性"得分。比字体问题更严重，属于结构级硬伤。
- **强制验证项**（DOCX 生成后全局检查）：
  - 全文最高层级是否只使用"一、二、三、四"（中文数字+顿号）？
  - 二级层级是否只使用"1. 2. 3."（阿拉伯数字+英文句号）？
  - 三级层级是否只使用"（1）（2）"（带括号的阿拉伯数字）？
  - 是否有任何符号（●◆▪）、字母（a.b.c.）、罗马数字混入序号体系？
- **本次是否检查**：待填写

### 🔴 遗漏15：表格列宽未根据内容自适应调整（⚠️ 阿云反馈）
- **发现日期**：2026-05-29
- **问题描述**：DOCX 中表格的列宽是等宽的，未按内容比例自适应分配。例如"序号"列占用了和"方案描述"列相同的宽度，导致长文字列被挤压成窄条。
- **根因**：Skill 规范明确写了"列宽按内容比例自适配分配，不做等宽"，但实际 DOCX 生成脚本未执行 `set_table_autofit(table)` + 内容驱动列宽。
- **规范要求**（来自 Step 3.5 三步实现法）：
  | 列类型 | 单格字数上限 | 建议列宽占比 |
  |--------|------------|------------|
  | 数据列（数字） | <=10字 | 8%-12% |
  | 清单列（名称） | <=20字 | 15%-25% |
  | 描述列（说明） | <=40字 | 30%-45% |
  | 备注列 | <=60字 | 20%-35% |
- **强制验证项**（DOCX 生成后逐表检查）：
  - 每张表的列宽是否按内容自适应（非等宽）？
  - 数据列（序号/数量/百分比）是否被压缩到合理窄度？
  - 描述列是否有足够宽度容纳文字？
  - 表格整体宽度是否撑满页面（非偏左/偏右）？
  - 是否有任何列的文字被挤压成单字竖排？
- **本次是否检查**：待填写

### 🔴 遗漏16：一级标题跑到目录前面、二级标题消失、文档从三级标题开始（⚠️ 阿云反馈）
- **发现日期**：2026-05-29
- **问题描述**：DOCX 生成后的导航窗格 / 实际文档结构中——
  - H1 一级标题出现在目录页（TOC）之前，而非之后
  - H2 二级标题在文档中完全不可见（被跳过或未渲染）
  - 文档正文实际上从 H3 三级标题开始，前两级结构缺失
- **根因分析**：
  - `doc.add_heading()` 被弃用后，手动构造段落的层级识别可能出错
  - TOC 域插入位置错误（应在第一个 H1 之前，而非之后）
  - 分页符插入逻辑导致第一个 H1 被推到了目录页之前
  - H2 的段落构造缺少或字体/字号设置导致在 Word 中不可见（可能白色字？未加 eastAsia 锁定？）
- **后果**：这是投标文件中**最严重的结构级故障**——目录没有对应的章节、导航窗格无法跳转、文档看起来像是从半截开始的。评委打开文件第一眼就能发现问题，直接拉低技术方案印象分。

  - 打开 DOCX -> Ctrl+A -> F9 更新目录 -> 目录中的章节编号是否与正文一致？
  - Word 导航窗格：H1 是否全部显示？H2 是否全部显示？H3 是否全部显示？
  - 第一个 H1 是否紧接在目录分页符之后（非之前）？
  - 正文第一页是否从「一、」或「二、」开头（非目录页）？
  - 任意层级缺失 -> 不得交付，必须修正后重新验证

### 🔴 遗漏17：表格上方残留 Markdown 格式的表格标记文字（⚠️ 阿云反馈）
- **发现日期**：2026-05-29
- **问题描述**：DOCX 正文中，表格上方出现残留的 Markdown 表格语法标记，以纯文本形式显示——
  - `| ---- | ---- | ---- |`（表格分隔行）
  - `| 序号 | 名称 | 参数 |`（表头行以 `|` 包裹）
  - 或表头行下方出现裸的 `| --- | --- |`
- **根因**：Markdown -> DOCX 转换脚本的表格解析逻辑不完善：
  - 识别到了表头行（`| 序号 | ...`）并生成了 DOCX 表格，但分隔行 `| --- |` 未被删除而当作普通段落渲染
  - 或者 Markdown 表格格式不标准（行首缺 `|`、行尾缺 `|`），导致整张表未被识别为表格，以纯文本落到了 DOCX 中
- **后果**：DOCX 中出现裸露的 `| --- |` 标记是**极其低级**的格式错误。投标文件中不应出现任何 Markdown 语法残留。
- **强制验证项**（DOCX 生成后全局搜索）：
  - 全文搜索 `|` 字符 -> 是否存在于表外的正文中？
  - 全文搜索 `---` -> 是否存在残留分隔行？
  - 全文搜索 `**` -> 是否存在未剥离的加粗标记？
  - 任何 Markdown 标记残留 -> 不得交付
- **本次是否检查**：待填写

### 🔴 遗漏18：文档中出现招标文件之外的自创数值/标准/英文（⚠️ 阿云反馈）
- **发现日期**：2026-05-29
- **问题描述**：方案正文中出现了以下三类"外来源"内容：
  - **自创数值**：非招标文件中的具体数字，如"3m x 2.5m""18°C~26°C""距离不超过 500m""5 分钟内响应"等
  - **自创标准**：非招标文件引用的标准/法规，如"符合 GB/T 19001-2016""参照 ISO 9001""执行《XX行业规范》"等
  - **自创英文**：招标文件白名单之外的英文，如"AI""IoT""SOP""KPI""PDCA"等
- **根因**：
  - 质量门1「内容合规」的自创数值检查被跳过
  - 质量门2「风格合规」的英文禁令被跳过
  - Phase 4A.4 英文扫描未实际执行或白名单不完整
  - Phase 4B 人工审阅清单中的"疑似自创数值列表"被忽略
- **后果**：自创数值/标准/英文是投标文件的**合规性红线**：
  - 自创数值（如"响应时间不超过 5 分钟"）如果与招标文件冲突 -> 可能被判定为虚假响应，直接废标
  - 自创标准（如引用招标文件未要求的国标）-> 多余，暴露了对招标文件研究不够
  - 自创英文 -> 违反编写原则第15条，降低专业性
- **强制验证规则（三零原则）**：
  - **零自创数值**：所有出现在方案中的具体数字，必须在招标文件中有出处。无出处的数字 -> 删除或改为定性描述
  - **零自创标准**：所有标准/法规编号，必须在招标文件的引用列表中有出处。无出处的标准 -> 删除
  - **零自创英文**：所有英文单词/缩写，必须在招标文件中出现过。未出现的英文 -> 替换为中文
- **本次是否检查**：待填写

## 服务类方案编写 — 已知遗漏

> v2.4.0 首次录入。以下 8 项为服务类方案编写的潜在风险点，基于货物类 18 项遗漏教训推断并适配服务类语境。实战触发后持续更新。

### 🟡 服务类遗漏S1：人员配置表未四层设计（引→名→形→释）
- **发现日期**：2026-06-01（预防性登记）
- **问题描述**：服务类方案中的人员配置表（组织架构、岗位职责、人员资质）缺少"引子"或"收束句"，表格变成孤立的附录插页
- **后果**：人员配置与方案正文脱节，评委无法快速理解人员安排与评分标准的对应关系
- **解决方案**：每张人员表必须检查引子→标题→版式→收束句四层完整
- **本次是否检查**：待填写

### 🟡 服务类遗漏S2：考核KPI数字自创（与招标文件不一致）
- **发现日期**：2026-06-01（预防性登记）
- **问题描述**：方案中考核KPI的具体数字（如"清洁达标率≥98%"）与招标文件规定的标准不一致
- **后果**：属于"三零原则"中的"零自创数值"违规。如果承诺的标准低于招标文件要求 -> 实质性负偏离；如果承诺的标准高于招标文件 -> 不可信且可能增加履约成本
- **解决方案**：所有KPI数字必须在招标文件中有出处。无出处的数字 -> 删除或改为定性描述
- **本次是否检查**：待填写

### 🟡 服务类遗漏S3：服务响应时限与招标文件存在细微偏差
- **发现日期**：2026-06-01（预防性登记）
- **问题描述**：方案中承诺的服务响应时限（如"30分钟内响应""2小时到场"）与招标文件规定存在1分钟/1小时级别的偏差
- **后果**：★条款中的响应时限不一致 -> 直接废标风险。属于"时间/数字交叉验证"中最容易被忽略的细节（看似差不多，实际差之毫厘）
- **解决方案**：Phase 4A.6 中增设"逐分钟/逐小时对比"环节。所有时间承诺必须与招标文件完全一致（不得">=2h"写成"2h内"）
- **本次是否检查**：待填写

### 🟡 服务类遗漏S4：人员岗位名称与招标文件不逐字一致
- **发现日期**：2026-06-01（预防性登记）
- **问题描述**：方案中使用的岗位名称（如"保洁主管"）与招标文件中规定的名称（如"清洁管理负责人"）不完全一致
- **后果**：人员配置是服务类方案的核心得分点。岗位名称不一致 -> 评委无法快速对号入座 -> 可能被判定为人员配置不满足要求
- **解决方案**：Phase 4A.2 交叉验证中增设"人员岗位名称逐字比对"。所有岗位名称必须与招标文件原文一致
- **本次是否检查**：待填写

### 🟡 服务类遗漏S5：考核体系未逐项响应评分标准
- **发现日期**：2026-06-01（预防性登记）
- **问题描述**：评分标准要求"提供完整的考核评估方案"，但方案只写了考核总则，未逐项覆盖招标文件中列出的KPI指标
- **后果**：考核体系是服务类方案的"验收标准"章节，评分权重通常较高。遗漏单项KPI -> 该得分点失分
- **解决方案**：Phase 2.3 二级标题生成时，必须将招标文件中列出的每个KPI指标映射为独立的二级标题
- **本次是否检查**：待填写

### 🟡 服务类遗漏S6：应急预案类型不完整（漏缺某种突发事件）
- **发现日期**：2026-06-01（预防性登记）
- **问题描述**：招标文件要求的应急预案类型（如"停水停电应急预案""群体性事件应急预案""疫情防疫应急预案"）中某项被遗漏
- **后果**：应急预案是服务类方案的高频主观分项。遗漏某一类预案 -> 该预案对应分数全丢
- **解决方案**：Phase 1.3 服务背景提取时，将招标文件中所有要求的应急预案类型列出清单，Phase 2.3 逐一映射为二级标题
- **本次是否检查**：待填写

### 🟡 服务类遗漏S7：培训方案只覆盖管理层、未覆盖一线岗位
- **发现日期**：2026-06-01（预防性登记）
- **问题描述**：培训方案仅写了管理层培训（项目经理、主管），未覆盖一线服务人员（保洁、保安、绿化）
- **后果**：服务类项目中一线人员占比通常>80%，培训方案只覆盖管理层 -> 评委判定为"培训体系不完整"
- **解决方案**：培训方案必须覆盖招标文件中列出的所有岗位类型，每个岗位至少对应一个培训子项
- **本次是否检查**：待填写

### 🟡 服务类遗漏S8：服务面积/体量数字在方案不同章节不一致
- **发现日期**：2026-06-01（预防性登记）
- **问题描述**：方案中第2章写的"服务面积50000㎡"，第5章变成了"约48000㎡"
- **后果**：同一份方案中的数字自相矛盾 -> 评委质疑方案的严谨性 -> 主观分扣分
- **解决方案**：Phase 4A.2 交叉验证中增设"全文档数字一致性扫描"。所有服务面积/体量/人数的数字在全文中必须唯一
- **本次是否检查**：待填写
