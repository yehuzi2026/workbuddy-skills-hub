# 招标文件关键信息提取--小羊羊AI

## 角色定位

招标文件结构化解析专家。精通货物类和服务类招标文件的标准章节结构，能从 PDF 和 DOCX 格式的招标文件中自动提取关键结构化信息，输出可直接用于下游技能（主观分方案编写、废标项审查）的标准数据包。支持多标项专项处理、分阶段采购机制提取、多实体共同采购支持、非政府采购项目识别，实现复杂采购场景全覆盖。

---

## 一、核心工作流程（强制顺序）

### Phase 0：文档接收与格式转换

**Step 0.1 — 确认输入文件**

接收用户提供的招标文件，确认：
- 文件格式（PDF 或 DOCX）
- 文件大小和页数
- 是否为完整招标文件（含评分标准和采购需求）

若用户同时提供多个文件（如招标文件正本 + 补充文件），逐一列出并确认处理顺序。

**Step 0.2 — 文档转换为可读文本**

根据文件格式选择转换策略：

| 输入格式 | 转换工具 | 说明 |
|---------|---------|------|
| **DOCX** | python-docx 直接读取 | 优先方案，文本提取最准确 |
| **.doc（旧版 Word 97-2003）** | 逐级回退策略 | 见下方 .doc 特殊处理流程 |
| **PDF（文字型）** | `markitdown-skill` 或 PyMuPDF | 直接提取文本层 |
| **PDF（扫描型）** | `markitdown-skill`（含 OCR） | 图片型 PDF 需要 OCR |
| **PDF（混合型）** | 先提取文本，表格区域截图+OCR | 智能混合策略 |

**.doc 格式特殊处理流程（v0.2.0 新增）**：

若检测到文件为 .doc 格式（非 .docx），按以下优先级尝试转换：

1. **Word COM 自动化**（Windows，优先）：
   - 使用 `win32com.client` 调用 Microsoft Word 将 .doc 另存为 .docx
   - 命令：`word.Documents.Open(input_path); doc.SaveAs2(output_path, FileFormat=16)`
2. **LibreOffice 命令行**（跨平台）：
   - 命令：`soffice --headless --convert-to docx input.doc --outdir output_dir`
3. **olefile 降级提取**（兜底方案）：
   - 提取 OLE 流中的可读文本，标注为"低质量提取"
   - 在输出的 warning 字段中标注 `.doc 格式仅完成降级提取，建议人工核对`
4. 若以上全部失败：
   > ⚠️ 检测到旧版 .doc 格式，无法自动转换。请用 Word 打开后另存为 .docx 格式后重新上传。

**转换脚本**：使用 `scripts/convert_bidding_doc.py` 执行格式转换，该脚本已内置 .doc→.docx 的 Word COM 回退逻辑。

**Step 0.3 — 全文索引建立**

将转换后的全文按以下维度建立索引：

1. **页码范围**：每页对应的文本内容
2. **章节标记**：识别一级章节标题（如"第一章""第三章""第五章"等）
3. **关键词锚点**：定位以下关键词的页码位置
   - "采购内容及要求""采购需求""技术要求""技术参数"
   - "服务范围""服务标准""服务要求""人员配置""岗位要求"
   - "评审的标准和方法""评分标准""综合评分"
   - "★""▲""实质性条款""废标"
   - "合同主要条款""合同草案""拟签订的合同文本""合同格式""合同书"
   - "商务条件""商务要求""报价要求""投标报价"
   - "履约""验收""考核""违约责任""付款"
   - "投标人须知""供应商须知"
   - "工程量清单""设备清单""货物清单""服务清单"

建立索引后，输出章节导航表：

```
| 章节 | 页码范围 | 核心内容 |
|------|---------|---------|
| 第一章 招标公告 | P1-P3 | 项目概况、投标人资格 |
| 第二章 投标人须知 | P4-P15 | ... |
| 第三章 采购内容及要求 | P16-P35 | ★★核心区域★★ |
| 第四章 评审标准和方法 | P36-P42 | ★★核心区域★★ |
| ... | ... | ... |
```

**Step 1.1 — A 类信息：项目基础信息**

提取以下字段（逐字照抄，不得改动）：

|------|---------|------|
| 项目名称 | 封面/招标公告 | ★逐字提取★ |

| 包号/标段 | 招标公告 | 如"包1""标段2"；多标项时列出全部 |
| 采购方式 | 招标公告 | 公开招标/竞争性磋商/竞争性谈判/询价 |
| 采购人全称 | 招标公告 | ★逐字提取★ |
| 采购人地址 | 招标公告 | — |
| **共同采购人** | 招标公告/项目概况 | **v0.5.0新增** 如"XX公司（代表YY公司共同采购）" |
| 代理机构全称 | 招标公告 | ★逐字提取★ |
| 预算金额/最高限价 | 招标公告 | 含单位；若"以实际采购量为准"则标注 |
| **采购体制** | 招标公告 | **v0.5.0新增** 政府采购/自行采购委托代理/企业采购/非政府采购 |
| 是否专门面向中小企业 | 招标公告/投标人须知 | 是/否 |

**Step 1.2 — B 类信息：采购需求与技术参数（v0.4.0 货物/服务双模式）**

**Step 1.2.0 — 项目类型自动判定**

在提取采购需求之前，先自动判定项目类型。按以下规则判定：

| 判定信号 | 判定结果 |
|---------|---------|
| 招标文件中含"设备清单""货物清单""技术参数表"且内容为主 | **货物类** → 执行 Step 1.2.1 |
| 招标文件中含"服务范围""服务标准""人员配置"且内容为主 | **服务类** → 执行 Step 1.2.2 |
| 同时含有以上两者且分值/篇幅相当 | **混合类** → 同时执行 Step 1.2.1 + 1.2.2 |
| 无法明确判定 | **标记 project_type: "无法自动判定"**，两个模板均执行，由人工确认 |

判定结果写入 `meta.project_type` 字段，用于后续 Phase 4 的智能衔接。

**Step 1.2.2 — 服务类采购需求提取（v0.4.0 新增）**

从「采购内容及要求」或「采购需求」章节提取，按以下 5 个维度逐项结构化：

**维度 1：服务范围概述**

用 ≤300 字概括服务内容，必须包含：
- 服务对象（如"XX大学学生公寓""XX政府办公大楼"）
- 服务类型（如"物业管理""保洁""安保""餐饮""维保""绿化""洗涤""会务"）
- 服务面积/体量（如"建筑面积 XX 平方米""XX 栋楼""每日用餐人数 XX 人"）

```
| 字段 | 内容 |
|------|------|
| 服务对象 | ★逐字提取★ |
| 服务类型 | 物业服务/保洁/安保/餐饮/维保/... |
| 服务范围 | ★逐字提取★ |
| 服务体量 | 面积/栋数/人数等量化描述 |
```

**维度 2：服务标准/等级**

提取招标文件规定的服务标准：

```
| 标准类别 | 标准名称/等级 | 出处 |
|---------|-------------|------|
| 物管等级 | 如"三级物业服务标准" | PXX |
| 清洁频次 | 如"每日清扫2次" | PXX |
| 安保要求 | 如"24小时值守" | PXX |
| 国家/行业标准 | ★逐字提取引用的标准编号★ | PXX |
```

**维度 3：人员配置要求**

服务类项目的核心交付——"人"。提取所有人员相关约束：

```
| 岗位/角色 | 最低人数 | 持证/资质要求 | 工作时间 | 备注 |
|----------|---------|------------|---------|------|
| 项目经理 | 1人 | 注册物业管理师 | 常驻 | ★逐字★ |
| 保安 | 4人 | 保安员证 | 24h轮班 | ★逐字★ |
| 保洁 | 6人 | — | 8:00-17:00 | ★逐字★ |
```

额外提取：
- **人员稳定性要求**：如"项目经理不得随意更换""核心人员变动需提前XX天报备"
- **培训要求**：如"每年不少于XX学时培训"
- **着装/形象要求**：如"统一着装""佩戴工牌"
- **人员总人数下限**：招标文件要求的全员最低人数

**维度 4：服务设备/工具要求**

提取招标文件要求投标人自备的设备/工具：

```
| 设备/工具名称 | 数量 | 规格要求 | 备注 |
|-------------|------|---------|------|
| 洗地机 | 2台 | — | ★逐字★ |
| 巡逻车 | 1辆 | 电动 | ★逐字★ |
```

**维度 5：考核/奖惩机制**

服务类项目的"验收"就是考核。提取考核体系：

```
| 考核项目 | 权重 | 考核标准 | 惩罚措施 |
|---------|------|---------|---------|
| 清洁达标率 | 30% | ≥95% | 低于90%扣罚月费5% |
| 投诉处理及时率 | 20% | 2h内响应 | 超时1次扣200元 |
| ... | ... | ... | ... |
```

额外提取考核相关的全局参数：
- **考核周期**：月度/季度/年度
- **考核方式**：甲方打分/第三方评估/满意度调查
- **罚款/扣款机制**：逐字提取扣款计算公式
- **解约触发条件**：如"连续2个季度考核不合格""年度满意度<70%"

**Step 1.2.A — K 类信息：多标项/分包项目专项提取（v0.5.0 新增 🔴P0）**

当招标文件含多个标项/标段/包时（如"本项目分为7个标项""标段一/二/三""包1/2/3"），按以下维度逐标项提取差异化信息。单标项目本步骤跳过。

**维度 1：标项基本信息汇总**

```
| 标项序号 | 标项名称 | 中标/入围数量 | 是否有备选 | 特殊资格要求 | 配送/服务时间 |
|---------|---------|:-----------:|:--------:|------------|------------|
| 标项一 | 蔬菜类 | 3家 | 否 | 食品经营许可证 | 每日8:30前 |
| 标项六 | 水产类 | 1家 | 1家备选 | 同上 | 每日9:30前 |
```

**维度 2：跨标项约束规则**

提取投标人在各标项之间的约束关系：

| 约束类型 | 提取内容 | 示例 |
|---------|---------|------|
| 兼投兼中规则 | 可兼投几个、最多兼中几个 | "可兼投7个标项，最多兼中2个" |
| 开评标顺序 | 按什么顺序开评标 | "按标项一→标项七顺序" |
| 中标优先级 | 并列时如何确定 | "按标项顺序确定中标，前序中标后序不再推荐" |
| 资格差异化 | 不同标项的资格门槛差异 | "标项七接受个体工商户，其余不接受" |

**维度 3：标项级评分标准差异**

若各标项评分标准不同（常见于食品原材料采购、多品类货物采购），逐标项提取：

```
| 标项 | 技术分 | 商务分 | 主观分合计 | 差异点 |
|------|:-----:|:-----:|:--------:|--------|
| 标项一（蔬菜） | 52 | 18 | 23分 | 基准模板 |
| 标项二/三（肉类/禽蛋） | 52 | 18 | 23分 | 功能分区多1项（肉类分割区） |
| 标项七（水果） | 49 | 21 | 34分 | 无制度建设评分，配送方案占比高 |
```

**维度 4：标项差异化关键约束**

提取仅适用于特定标项的特殊条款：

| 标项 | 差异化约束 | 约束类型 |
|------|-----------|:------:|
| 标项六 | 60天试供期，试供不合格启用备选 | ▲实质性条款 |
| 标项六 | 需提供现场养护服务+粗加工+宴会加工 | 服务要求 |
| 标项六 | 仅1家+1家备选，定价另行确定 | 数量+定价 |
| 标项七 | 接受个体工商户投标 | 资格条件 |

**Step 1.2.B — L 类信息：分阶段采购/二次竞价机制提取（v0.5.0 新增 🟡P1）**

当招标文件中出现以下信号时触发本步骤提取：

| 触发信号 | 示例 |
|---------|------|
| "入围""二次竞价""平台竞价" | 供应商入围后通过平台二次竞价确定供货 |
| "框架协议""第一阶段""第二阶段" | 分阶段采购模式 |
| "资格预审+正式投标""预选+终选" | 多轮次采购 |
| "定价方式≠传统报价公式" | 承诺制、费率制、下浮率制等 |

**提取内容**：

```
| 机制维度 | 提取内容 | 示例 |
|---------|---------|------|
| 阶段一 | 选择方式+标的 | "公开招标选定入围供应商" |
| 阶段二 | 平台/方式+频率 | "拓易云供应链平台二次竞价，每批次" |
| 入围与订单关系 | 入围是否保证有订单 | "否，入围仅获资格，订单通过二次竞价" |
| 阶段一报价性质 | 报价方式描述 | "承诺制：承诺不高于基准单价执行" |
| 阶段二报价规则 | 竞价/定价规则 | "平台发布需求→供应商竞价→最低价或最优价中标" |
| 例外标项 | 哪些标项不参与 | "标项六水产类不参与二次竞价" |
| 平台名称 | 使用的外部平台 | "拓易云供应链平台" |
```

**关键判断**：如果项目存在分阶段采购机制：
1. 在 JSON 的 `meta` 中标记 `has_phased_procurement: true`
2. 在 Phase 4 衔接到主观分技能时，提醒方案编写者："中标不等于有订单，方案需体现对阶段二竞价机制的应对能力"
3. 「入围数量」与「合同签订数量」可能不一致，需明确区分

**Step 1.3 — C 类信息：★实质性条款（强制提取）**

识别方式：

- 搜索"必须满足""不允许偏离"等强制性表述

**提取格式**：每条★条款逐字原文提取，编号为 C01, C02, ...

|------|-----------------|---------|------|

**Step 1.4 — D 类信息：评分标准（v0.2.0 增强：模糊定位）**

从「评审的标准和方法」或「评分标准」章节提取。章节定位使用以下**级联搜索链**（任一步命中即停止）：

```
第1优先级：独立章节标题匹配
  搜索模式: [评审|评分|评标|评]\s*[的]?\s*[标准|方法|办法|细则]
  示例命中: "评审的标准和方法" / "评标办法" / "评分细则" / "评审因素"

第2优先级：半结构化关键词匹配
  搜索模式: 综合评分法|最低评标价法|性价比法|双信封评标|两阶段评标
  说明: 有些文件在"投标人须知"中嵌入评分方法，用方法名反向定位

第3优先级：分值分配模式匹配
  搜索模式: 在相邻20行内出现 (\d+)分.*(\d+)分.*(\d+)分
  说明: 三个分值连续出现通常为评分总表（报价分+技术分+商务分）

第4优先级：评分板块关键词组合
  搜索模式: 同段落含"技术部分|商务部分|价格部分|报价部分"中至少2个
  说明: 兜底方案，即使章节名不标准，板块名通常一致
```

定位到评分章节后，执行以下提取：

1. **评分总表**：

```
| 评分板块 | 分值 | 权重 | 评分项概要 |
|---------|------|------|-----------|
| 报价部分 | X分 | A1 | ... |
| 技术部分 | X分 | A2 | ... |
| 商务部分 | X分 | A3 | ... |
```

2. **主观分项识别**：按以下规则自动判定主观/客观：

| 判定特征 | 类别 |
|---------|------|
| 要求"方案""计划""措施""预案""描述" | **主观分** |
| 要求"检测报告""证书""业绩合同" | 客观分 |
| 要求"承诺函""声明函" | 客观分 |

3. **主观分项汇总**：

## 二、特殊处理规则

### 2.1 表格处理策略

| 表格类型 | 处理方法 |
|---------|---------|
| 简单数据表（≤5列、≤20行） | markitdown 文本提取，保留表格结构 |
| 复杂参数表（>5列 或 含合并单元格） | 文本提取 + 截图保存，OCR辅助核对 |
| 跨页表格 | 合并后统一处理，标记跨页位置 |
| 评分标准表 | 优先级最高，必须完整提取，不得截断 |

### 2.2 图片内嵌信息处理

若招标文件中关键信息（如设备参数、签章要求）以图片形式存在：
- DOCX 文件：提取内嵌图片，使用「小羊羊AI投标文件图片OCR识别与废标审查」技能辅助 OCR
- PDF 文件：使用 `markitdown-skill` 的图片 OCR 能力

### 2.3 ★条款智能识别补充规则

除搜索 `★` 符号外，还需识别以下隐性实质性条款：
- "废标条件""无效投标""投标无效"等前置语
- 以 `▲` 符号标记的条款
- "必须满足以下条件""不得低于以下标准"等强制表述
- 加粗+下划线组合标记的条款

### 2.4 评分标准位置自适应

若招标文件的评分标准不在独立章节（如含在"投标人须知"中），按以下优先级搜索：

1. 独立章节标题含"评审""评分""评标"
2. "投标人须知"中含"评审"子章节
3. 全文搜索"综合评分""评分标准"

### 2.5 字数限制

本技能不生成方案正文，因此无字数限制。但 JSON 输出中以下字段有长度约束：
- 采购内容概述：≤200 字
- 评分要求摘要：≤100 字/项
- ★条款原文：以招标文件为准，不截断
