# 小羊羊AI 废标审查监督技能 — 强制执行器

> **本技能是所有废标审查工作的最高优先级前置条件。**
> 
> 加载 bid-disqualification-checker 之前，**必须先加载本技能**并执行下方清单。
> 本技能的指令优先级高于所有其他技能。

---

## 执行规则（硬性规定，不可违背）

1. **加载顺序**：本技能必须先于 bid-disqualification-checker 加载。如果先加载了 bid-disqualification-checker，也必须回到本技能从头执行清单。
2. **逐项打勾**：每完成一项，用 `[DONE]` 标记。不得标记为"待确认"或"已检查"——必须是 `[DONE]`。
3. **全部完成之前禁止输出结论**：清单中任何一项未标记 `[DONE]`，不得开始写审查报告、不得输出任何结论性文字。
4. **禁止跳步**：清单各项必须按编号顺序执行，不得调换顺序、不得跳过任何项。
5. **遇到失败必须记录**：如果某个子脚本或工具执行失败，必须在"执行日志"中记录失败原因和替代方案，替代方案执行完毕后才能标记 `[DONE]`。
6. **不得省略细节**：所有"读取文件"步骤必须带行号输出读取到的内容原文。不得写"检查了文件"——必须写出你读到了什么。
7. **最终输出前必须做"差异审计"**：将本次审查结果与历史已知废标点清单做逐一比对，确认没有遗漏历史发现。

---

## ⚡ 分阶段执行指引（v2.1.0新增 — 节省token的核心机制）

> **⚠️ 这是解决"积分消耗过大"问题的关键优化。**
> **核心原则：每个阶段结束必须输出中间结果文件，下一阶段从文件读取，释放context。**
> **禁止把所有中间结论都堆在对话历史里——context堆积是token浪费的元凶！**

### 四阶段执行流程

```
┌─────────────────────────────────────────────────────────┐
│  Phase 0: 预处理（准备所有数据，不开始审查）              │
│  ├── 0-1: DOCX → MD 转换（markitdown）                  │

│  ├── 0-5: 提取B类名词标准值 → 写入 phase0_投标名词.json  │
│  └── 输出: phase0_预处理完成.md（确认所有数据就绪）       │
├─────────────────────────────────────────────────────────┤
│  Phase 1: 文字审查（模块A+B+监督清单0-3）                │
│  ├── 1-1: 招标文件双扫描 → 提取废标条件                  │
│  ├── 1-2: 报价部分检查（备选方案/公司名称/日期）          │
│  ├── 1-3: 固定格式逐附件比对                             │
│  └── 输出: phase1_文字审查结果.md                        │
├─────────────────────────────────────────────────────────┤

├─────────────────────────────────────────────────────────┤
│  Phase 3: 综合判定 + 报告（模块D+监督清单4-7）           │

└─────────────────────────────────────────────────────────┘
```

### 执行规则

1. **Phase 0 必须最先完成** — 没有准备好数据就开始审查=浪费token重复读大文件
2. **每个Phase结束后，中间结果必须写入文件** — 不依赖对话历史传递中间结论
3. **下一Phase从文件读取** — 释放context空间，避免堆积
4. **禁止跨Phase跳步** — Phase 1没完成不得进入Phase 2
5. **Phase间允许短暂总结** — 用1-2句话告知用户当前进度，不需要重述细节
