# 工程造价审计 AI 助手 · 使用示例

> 本助手是「审清（主理人）+ 5 角色」协同的造价审计专家团。本文给出可直接照抄的用法，覆盖最关心的四件事：**上下文怎么给、问题怎么拆、边界怎么防、结果怎么验**。

## 0. 一句话启动
把需求直接发过来即可，例如：
- 「帮我审一下这份竣工结算书，看看审减空间在哪」
- 「这个签证单该不该认，能索赔多少」
- 「按合同约定的清单规范版本，这个分部分项怎么组价」
- 「这两张表是对量，帮我找出量差、价差和漏项」（同时发两版表格，或用 `reconcile.py`）
- 「按这几条抽查结果出审计底稿和检查范围方案」

审清会先判断归口角色，缺信息就一次性问清（见第 1 节），不会瞎编数字。

> ⚠️ **计价依据版本**：以**合同约定**为准。合同约定按 GB 50500-2013 执行的既有项目仍按合同履行；2025-09-01 之后签约 / 招标的项目按 GB/T 50500-2024 与合同执行。不清楚时请直接说明合同是怎么约定的——这比问「该用哪版」更关键。

## 1. 主理人（审清）怎么采集上下文
开工前审清会抽 4 类信息，缺失则按清单回问：

| 维度 | 要搞清楚的点 | 示例问法 |
|---|---|---|
| 项目画像 | 业态（房建 / 市政 / 安装…）、规模、所在地 | 「这是住宅还是厂房？大概多少平米？」 |
| 阶段 | 招标 / 施工 / 结算 / 审计 / 后评估 | 「现在做到结算了，还是已经在审计？」 |
| 交付诉求 | 算量 / 审减 / 索赔 / 组价 / 指标？ | 「你最想要的是审减额还是合规意见？」 |
| 硬约束 | 合同约定的清单 / 定额版本、合同类型、依据规范 | 「合同是固定总价还是单价合同？约定按哪版清单？」 |

**带文件更高效**：把合同、图纸、结算书、签证单、变更令直接发到对话，对应角色会先 Read 再答，比纯文字描述准确得多。Excel 清单 / 结算表、PDF 可交给 `ingest.py` 原生解析。

## 2. 5 个角色怎么拆问题（典型触发与拆解）

### 结算清（结算审核师）
- **触发**：「审这份结算」「核对报送与审核差异」
- **拆解**：① 核合同口径（单价 / 风险范围）→ ② 对量（清单项 + 变更签证）→ ③ 核价（材料调差 / 信息价）→ ④ 算审减额与审减率 → ⑤ 交叉验证
- **边界**：合同外签证无甲方签字不认；材料涨价超风险幅度才调；暂列金额未使用须扣回
- **验证**：审减率 = 审减额 / 送审价，反向用「审核价 = 送审价 − 审减额」验算

### 审计明（造价审计师）
- **触发**：「独立审计这项目」「合规性与真实性核查」
- **拆解**：① 程序合规（招投标 / 合同）→ ② 量价真实（抽查分项）→ ③ 变更索赔合规 → ④ 出具审计意见
- **边界**：无签字凭证不计入；甲供材不得重复计取；规费税金按当地文件
- **验证**：抽查项合价合计应等于报告汇总，勾稽关系闭合（`--func reconcile_check`）；审减额须能拆成量差 + 价差并可反向验算（`--func audit_attribution`）

### 索赔通（索赔分析师）
- **触发**：「工期延误能索赔吗」「窝工损失怎么算」
- **拆解**：① 定性（是否业主风险 / 不可抗力）→ ② 定量（工期 / 费用）→ ③ 时限（28 天报索赔意向 + 最终报告时限）→ ④ 依据（合同专用条款）
- **边界**：承包人原因不赔；未及时发索赔通知可能失权；利润索赔仅限特定情形
- **验证**：费用索赔 = 实际额外支出 − 合同内已含；工期索赔须扣除同期承包人自身原因造成的延误

### 清单准（清单计价师）
- **触发**：「这清单怎么组价」「综合单价合不合理」
- **拆解**：① 列清单项 → ② 套定额 / 市场价 → ③ 算人材机 → ④ 管利规税 → ⑤ 合价
- **边界**：清单与定额计量单位须一致；特征描述决定组价；甲供材计税视合同
- **验证**：用 `calc_engine.py` 跑清单合价，再人工抽检 3 项复核。组价缺人材机单价时会**直接报错**（fail-closed），不会静默按 0 计算——请先导入当地价格数据。

### 指标衡（指标分析师）
- **触发**：「单方造价合理吗」「跟类似项目比如何」
- **拆解**：① 取指标（单方造价 / 含量）→ ② 比基准（类似工程 / 数据库）→ ③ 找偏差 → ④ 给结论
- **边界**：不同业态 / 地区不可直接比；指标须同口径（含 / 不含土方、精装）；样本不足要标注
- **验证**：指标 = 总造价 / 计算面积，反向用「总造价 = 指标 × 面积」验算

## 3. 协作交接（多角色怎么一起上）
- **并行**：清单准（组价）与指标衡（指标）可同时跑
- **串行**：清单准先出清单 → 结算清拿去核结算；审计明在结算清之后做独立复核
- **标准工单**：每个角色产出都带「依据 / 假设 / 结论 / 风险提示」，由主理人汇编成报告

## 4. 给你的结果验证清单（拿到答案后这样核）
1. **数字有出处**：每个关键数都标了依据（条文 / 文件 / 你给的资料）？没标的要追问
2. **反向验算**：审减额、合价、指标都能用逆运算核对一遍
3. **单位口径**：面积用建筑 / 结构 / 幕墙面积？材料单位 t/m3/m2？金额是「元」还是「万元」？前后必须一致——本助手严禁把「元」的结果标成「万元」
4. **边界是否点明**：风险幅度、签字要件、时限、甲供材这些「坑」有没有提示
5. **假设要确认**：模型替你默认的参数（如信息价月份、取费类别、基准价）是否符实
6. **工具自检**：涉及计算的，应走 `calc_engine.py` 实算并附调用证据；可要求跑 `python calc_engine.py --selftest`（应显示 99/99 全过）
7. **门禁是否放行**：正式交付的稿子应经统一门禁，未过门禁的稿子不得对外发出（见第 5 节）

## 5. 门禁怎么用（正式交付前）
```bash
python references/search/gate.py emit --file 草稿.md        # 放行前唯一通道（推荐文件模式）
python references/search/gate.py selfcheck 报告.md          # 交付文件末道拦截（可多个文件）
python references/search/gate.py log --limit 20             # 查看最近的门禁留痕
python references/search/authority_search.py "工程量偏差"     # 查条文号（命中退出码 0）
python calc_engine.py --selftest                            # 引擎自检（应 99/99 全过）
python e2e_smoke_test.py                                    # 全工具冒烟自检（应 71/71 全过）
python content_check.py                                     # 包完整性 + 文档/代码/配置一致性 + 题库答案逐题复算
```
- 退出码 0 = 已放行（PASS / WARN）；退出码 1 = 已拦截，**该内容不得输出**，须按提示补依据、查条文号，或改成经验估算并显式标注；
- **金额要能溯源**：金额（元 / 万元 / 亿元）光有规范条文号还不够，必须给数据来源（送审资料 / 合同 / 签证 / `local_rates.json`）或计算式（如 `12000-10900=1100 万元`）——条文只能证明计价「规则」，不能证明「本项目的金额」；
- **Windows 下不要用 `echo ... | python gate.py`**：PowerShell 5.1 会把中文变成 `???`，数字依据全废，门禁会直接报「编码损坏」。请用 `--file` 模式，或先把草稿落地成文件。

## 6. 审计作业过程怎么用（对量 / 底稿 / 实施方案 / 台账 / 成套档案）

前面 1~5 节解决"算得准、有依据"；本节解决**作业过程怎么落地、档案怎么成套**——审计的产出物不只是一段结论，而是可复核的底稿与台账。

### 6.1 两版数据对量（最高频的一步）
```bash
python reconcile.py --left 送审.xlsx --right 审定.xlsx --key 项目编码 --qty 工程量 --price 综合单价 --unit 元 --project 某住宅项目 --source "送审结算书与审定对比表"
```
- 输出：`对量差异明细.xlsx`（逐项：量差 / 价差 / 漏项 / 增项）+ `对量差异分析.md`（Top 差异、漏项/增项清单、口径提示），并自动过门禁；
- 报告里做了**四项闭合校验**：量差 + 价差 + 漏项 + 增项 ≡ 总差额——不闭合就说明匹配键或口径有问题，先解决再谈审减；
- 只有金额列（没有量、价列）时去掉 `--qty/--price`，改用 `--amount 合价` 即可；
- 单位必须与表一致：表是万元就 `--unit 万元`，不要混。

### 6.2 审计底稿
```bash
python -c "import deliverable as d; d.workpaper(items, meta, './_out')"
```
- 每份底稿九要素：索引号 / 审计事项 / 检查程序 / 查证过程与证据 / 依据（含**计价依据版本**）/ 涉及金额与计算 / 审计结论 / 编制与复核签署 / 数据来源；
- 清单表**逐行自带「证据与数据来源」列**，做到底稿金额可回溯；
- 没有索引、没有证据的金额进不了报告——这是本团底稿铁律。

### 6.3 检查范围方案（实施方案）
- 用引擎 `sample_plan`：大额必查 + 覆盖率控制，输出必查 / 抽中 / 未覆盖三类；
- `audit_plan()` 直接生成《审计实施方案》xlsx + md，含检查程序、进度分工与**抽样口径免责声明**；
- ⚠️ 这是工程审计常用的实务抽样，**不是统计抽样**；委托方要求统计抽样或已定重要性水平的，须另行设计。

### 6.4 资料索取清单、问题台账、争议台账
- `pbc_list()`：开工先发资料清单，超期未提供要书面催告并记录（必要时在报告中说明审计范围受限）；
- `issue_register()`：发现问题 → 整改要求 → 期限 → 状态（未整改 / 整改中 / 已销号），销号须有实质证据；
- `dispute_register()`：有分歧的事项单独建账（主张 / 审核意见 / 双方依据 / 处理建议 / 状态），不影响无争议部分先行结算。

### 6.5 成套项目档案（把「审计实施方案」接到真实项目上）
```bash
python project_template.py --save-template 项目信息.json        # 1) 先导出空白模板（UTF-8，含全部可填字段）
# 2) 用项目真实信息把 项目信息.json 填好，填不出来的先留「（待填）」
python project_template.py --meta 项目信息.json --out ./某住宅项目审计档案
```
- 一条命令生成**六卷固定目录 + 00 项目索引**，共 **30 份文件**（含 xlsx）：
  ① `01_审前调查与立项` —— 审前调查表 / 独立性声明与保密承诺 / **外聘人员与回避记录** / 审计组分工与联系方式；
  ② `02_审计实施方案`（十四节）—— 编制依据·目标·范围与内容·方法与程序·检查范围与抽查方案·进度·分工与三级复核·质量控制·配合事项·交付物清单·计价依据版本，外加**重点风险领域与应对措施**（风险→程序对照，具体情形留「（待填）」）、**方案调整与报批**、**编制/复核/批准签署栏** + 检查范围与抽样方案表；
  ③ `03_资料索取与交接` —— 资料索取清单 PBC / 资料交接签收单；
  ④ `04_审计底稿与证据` —— 底稿目录与索引规则 / 审计底稿 / 证据清单与证据链台账 / **现场取证记录单** / **抽样见证记录** / **电子数据取数说明** / **三级复核意见记录表** / **证据附件页码索引**（报告金额 → 底稿索引 → 附件页码） / **审计日记与工作记录**（按日留痕、挂接底稿索引）；
  ⑤ `05_问题与争议` —— 问题整改台账 / **整改回访记录**（回访核实与销号证据） / 争议事项台账；
  ⑥ `06_报告与归档` —— **征求意见与沟通记录**（反馈意见逐条答复）/ **期后事项与追溯调整记录** / 审计报告征求意见稿骨架 / 卷内目录与归档说明。
- **缺数据一律留「（待填）」，工具绝不代填**：先跑出骨架，数据到齐后补齐 JSON 再重跑同一条命令，整套档案一起刷新；
- 实施方案第五节的必查 / 抽中 / 未覆盖由引擎 `sample_plan` 实算（抓大放小 + 覆盖率控制，**非统计抽样**）；没提供检查范围明细时，会如实写明「尚未生成」及生成规则，而不是编一份出来；
- 生成后**每份 Markdown 逐份过门禁**：有文件未放行会被逐条列出，并返回非 0 退出码；
- **页码索引与报告附件目录联动**：填了 `证据附件清单` 后，报告第七节「附件目录」会自动编号（附件编号 + 底稿索引 + 起止页码）；某一项没填页数，它及其后的页码一律留「（待填）」，等装订后手工补——**工具不会替你猜页码**；
- 想先看效果：`python project_template.py --demo --out ./_project_demo`（内置示例住宅项目，可直接跑）；
- ⚠️ 别用 PowerShell 的 `>` 去接模板（会写成 UTF-16），要用 `--save-template` 落盘；
- 生成的 `templates/项目信息表.template.json` 与代码同源，可直接复制一份当填写底稿。

### 6.6 问题定性拿不准，先找依据
```bash
python issue_pair.py "地下车库土方重复计量，多计 320 万元"      # 用问题描述找
python issue_pair.py --定性 "多计·材料调差"                    # 或直接给定性
python issue_pair.py --list                                     # 看看有哪些定性类别
```
- 输出：命中的**定性类别**、**建议依据**（标准号 + 条款 + 效力 + 适用条件 + 要点）、**常见处理**、**证据要求**，并明确标注「⚠️ 条款号须核验」；
- **未命中会如实说未命中**（退出码 1），并自动转向 `authority_search.py` 检索条文——不会给你编一条出来；
- 生成的**问题整改台账**会自动带一列「建议依据（须核实）」，逐条配好，复核时直接引；
- 注意：这是**建议依据**，不是结论。定性看事实与合同，依据要核对官方原文，最后仍由审计人员签认。

### 6.7 手上几个项目，出一份总台账
```bash
python project_template.py --portfolio ./各项目所在目录 --out ./审计项目总台账
```
- 自动扫描目录下所有项目档案的 `项目信息.json`，汇总成 xlsx + md：项目 / 当前阶段 / 送审与审定 / **审减额与审减率** / 问题数与**未销号数** / 争议数；
- 缺项留「（待填）」，合计**只累计有值的行**；补全项目信息后重跑即可刷新；
- 总台账是**进度与问题总览**，不替代各项目档案里的正式文件。

> 一句话：**先对量定位 → 再建底稿坐实 → 方案划范围 → 台账管闭环 → 成套归档 → 定性有依据。**

### 6.8 电子数据校验值登记（证明取来的文件没被动过）
```bash
python ingest.py --hash 计量支付台账导出.xlsx                       # 登记：算 SHA-256 与 MD5
python ingest.py --hash 计量支付台账导出.xlsx --expect <原登记值>    # 使用前：重算比对（不一致退出码 1）
```
- 把「导出时间 + 记录数 + 校验值」三件套填进档案的 `04_审计底稿与证据/电子数据取数说明.md`；
- 纪律：**取数时算一次，此后每次使用前重算比对**；不一致说明文件已被改动，不得使用，须重新取数；
- 注意：校验值只证明「文件没被改动」，**不证明「数据本身真实」**——记录数比对、金额合计比对、原始凭证核对一样不能省。

### 6.9 审计日记、整改回访与回避记录（过程留痕）
- **审计日记**：填 `项目信息.json` 的 `审计日记`（日期 / 参与人 / 工作内容 / 挂底稿索引 / 发现问题 / 处理与下一步 / 耗时），生成 `04_审计底稿与证据/审计日记与工作记录.md`；会议、询问、踏勘另填 `工作记录`；
- **整改回访**：填 `整改回访清单`，生成 `05_问题与争议/整改回访记录.md`——销号要拿得出证据（金额类：退款 / 冲减 / 重新结算凭证；制度类：修订文件或发文；程序类：补签补办手续原件）；
- **回避与外聘**：填 `外聘人员清单`、`回避声明清单`，生成 `01_审前调查与立项/外聘人员与回避记录.md`（外聘人员报酬不得与其意见、认定金额挂钩）；
- 这三类都属于**过程留痕**：结论在底稿、过程在日记与回访记录，复核时互相印证；
- 想一次看全：`python project_template.py --demo` 的示例档案里这几份都是填好的样子。

> 一句话：**报告金额查得到页码、电子数据证得了未改动、每一步作业留得下痕迹。**
## 7. 常见误用提醒
- 别只甩一句「帮我审一下」——给项目画像和文件，质量差十倍
- 别把测算当结论用——本助手给的是专业测算，重大结算 / 审计仍须注册造价师签章
- 别拿示例占位数据当真实价格——`local_rates.example.json` 只是格式样例，须替换为当地公布数据
- 别忽视时效——法规有时效，助手会跑时效巡检并标注「⚠️ 待核验」项，但请以最新官方文件为准
- 别把敏感资料外传——你提供的合同 / 结算书 / 报价仅限本次任务使用，对外举例一律脱敏
- 别把练习当真题——题库与案例均为模型自编 / 脱敏构造，不对应任何官方真题或真实项目
- 别把对量表当审定结论——`reconcile.py` 是**定位工具**，差异要逐项查清原因（真漏计 / 不予认可）后才谈审减
- 别跳过底稿直接出报告——报告里每一项金额都要能指回底稿索引、底稿里每一项金额都要能指回具体证据
- 别把「建议依据」当结论——`issue_pair.py` 给的是定向核查用的条款线索，条款号仍须核对官方原文，定性须由审计人员确认
- 别用总台账代替档案——多项目总台账只是进度与问题总览，正式结论仍在各项目档案的底稿与报告里
- 别漏了过程留痕——取证要有记录与见证、抽样要有方法与见证人、取数要有完整性校验、复核意见要具体到索引号，否则复核时说不清
- 别让反馈意见悬着——对方的意见要逐条答复（采纳 / 部分采纳 / 不采纳 + 理由），期后拿到的新证据要记进期后事项
- 别跳过校验值——电子数据导出件要登记 SHA-256 / MD5，使用前重算比对；只记记录数不记校验值，说不清文件有没有被动过
- 别让页码缺口带出假页码——附件页数没填完就留「（待填）」，装订后手工补；跳着累加出来的页码全是错的
- 别拿台账状态当销号依据——销号前要有回访核实与实质性证据（凭证 / 制度文件 / 补办原件），口头或书面「已整改」不算
