# 06 审计底稿与证据链（审计作业核心）

> 适用角色：审计明（造价审计师）、结算清（结算审核师）、审清（主理人复核）。
> 本文解决一个问题：**凭什么说这个数是对的**——把"结论"落成"可复核的底稿 + 可指认的证据"。

## 一、两条铁律

1. **报告里的每一项金额，都要能指回一份底稿的索引号。**
2. **底稿里的每一项金额，都要能指回一份可指认的证据。**

链条：结论 ← 底稿 ← 证据 ← 原始资料（合同 / 图纸 / 计量台账 / 签证单 / 发票 / 付款凭证）。
任何一环断开，该金额只能进"待核事项"，不得进结论。

## 二、底稿必备九要素（缺一不可）

| # | 要素 | 要求 |
|---|---|---|
| 1 | 索引号 | W-01、W-02……，与报告金额一一对应，不得跳号、不得一号多项 |
| 2 | 审计事项 | 对应哪个程序、哪个分部分项 |
| 3 | 检查程序 | 做什么、怎么做、抽查比例、抽样方法（全查 / 按金额抓大放小 / 按覆盖率抽查） |
| 4 | 查证过程与证据 | 查了哪些资料、证据附件序号、复核过的计算式 |
| 5 | 计价依据 | 合同条款 / 规范条文号 / **计价依据版本**（GB 50500-2013 或 GB/T 50500-2024，以合同约定为准） |
| 6 | 涉及金额与计算过程 | 单位口径写明（元 / 万元），计算式可反向验算 |
| 7 | 审计结论与定性 | 多计 / 少计 / 口径错误 / 程序不合规 / 待核事项 |
| 8 | 编制与复核签署 | 编制人、复核人、日期，复核意见留痕 |
| 9 | 数据来源 | 每一行金额的取数来源（送审资料 / 台账 / 实算命令） |

> 工具：`deliverable.py` 的 `workpaper(items, meta, out_dir)` 直接产出 `审计底稿.xlsx` + `审计底稿说明.md`，
> 清单表每行自带「证据与数据来源」列，可逐行过输出门禁。

## 三、证据分级与强度

| 等级 | 典型证据 | 能否直接支撑审减 |
|---|---|---|
| 强 | 双方签认的签证/变更单、经监理签认的计量记录、发票 + 付款凭证、有签认的竣工图 | 可以 |
| 中 | 单方记录但有第三方佐证（监理日志、进场记录、影像资料、往来函件） | 须补强，或与强证据组合成链 |
| 弱 | 事后回忆、口头说明、无签认的内部台账、事后集中补签件 | 不可以，只能列入待核事项 |

**判定顺序**：先看有没有证据 → 再看证据够不够强 → 最后才看金额对不对。
**反向警示**：仅有弱证据支撑的金额，不得直接作为审减结论写入报告。

## 四、证据链闭合的四个检查点

1. **时间链**：指令（变更/签证）→ 实施 → 计量 → 验收 → 计价的先后顺序是否合理，有无倒签迹象；
2. **主体链**：签认人是否在授权范围内（甲方代表、监理工程师、总监代表），有无越权签认；
3. **数量链**：图纸量 / 计量量 / 结算量 / 领料量（甲供材）四者能否相互印证；
4. **金额链**：单价来源 → 合价 → 取费 → 汇总 的复算闭环，单位口径（元 / 万元）全程一致。

## 五、高频证据缺陷与审计动作

| 缺陷 | 识别信号 | 审计动作 |
|---|---|---|
| 事后集中补签 | 同一签名日期批量覆盖数月事项 | 比对监理日志、施工日志、材料进场时间 |
| 签认人越权 | 签字人无授权文件 | 索取授权书或授权范围说明 |
| 数量无来源 | 签证只有结果数、无计算式与草图 | 要求补充计算书，或以现场记录倒轧 |
| 单价无来源 | 无认价单、无组价过程 | 查认价单、同期信息价、重新组价并留痕 |
| 图文不符 | 签证部位与图纸轴号/图号对不上 | 现场核位，或要求补充定位记录 |
| 证据缺失 | 只有结算书、无支撑资料 | 发资料索取清单（`pbc_list`）并记录超期未提供 |

## 六、三级复核与签署

- 审计员编制 → 主审（复核人）复核 → 项目负责人签发；重大项目须复核留痕。
- 复核要点：① 数字复算一致；② 依据引用准确（条文号 / 合同条款）；③ 结论与证据匹配、定性恰当；④ 单位与口径一致；⑤ 索引与报告金额对应。
- **未经复核的底稿不得作为报告依据**；复核意见与修改痕迹须保存在底稿中。

## 七、底稿必做的两道验算

1. **勾稽验算**：分项合计 = 报表汇总数；差额须逐项查清原因，**不得以"四舍五入/尾差"解释**。
   `python calc_engine.py --func reconcile_check --parts "8000;4000" --total 12000 --tolerance_rate 0.5`
   （`--parts` 用分号分隔分项金额；允差可给绝对值 `--tolerance`，或按汇总数比例的百分数 `--tolerance_rate`）
2. **审减归因验算**：审减额 = 工程量核减影响 + 单价核减影响，且可反向验算。
   `python calc_engine.py --func audit_attribution --submit_qty ... --audited_qty ... --submit_price ... --audited_price ...`
   报告必须写清"审减是因为多报量还是高报价"。

**两版数据对量**（送审 vs 审定逐项比对，自动拆出量差 / 价差 / 漏项 / 增项并做闭合校验）：
`python reconcile.py --left 送审.xlsx --right 审定.xlsx --key 项目编码 --qty 工程量 --price 综合单价`

## 八、检查范围与审计范围限制

- 检查范围方案用 `sample_plan`："抓大放小 + 覆盖率控制"，**不是统计抽样**，不得对外表述为统计抽样结论。
  `python calc_engine.py --func sample_plan --sample_items "土建:5200;安装:3100;装饰:1600" --threshold_rate 0.05 --coverage_target 0.70`
  （`--sample_items` 用分号分隔、每项「名称:金额」）
- **未覆盖项不代表无风险**；无法取得证据、被审计单位不配合的，构成审计范围限制，须在报告中如实披露，
  不得以抽样结论替代整体意见。
- 交付：`deliverable.py` 的 `audit_plan(items, meta, out_dir)` → `审计实施方案.xlsx` + `审计实施方案说明.md`。

## 九、问题台账与整改闭环

- 审计报告出具不是终点：发现须转成**问题台账**（问题描述 / 定性 / 涉及金额 / 依据 / 责任单位 / 整改要求 / 期限 / 状态）。
- 状态口径：未整改 → 整改中 → 已销号；销号前须**回访核实并留痕**（见 `05_问题与争议/整改回访记录.md`），销号须有实质性证据（补正资料、退款凭证、制度修订文件），不得"一函了之"。
- 交付：`deliverable.py` 的 `issue_register(issues, out_dir, meta)` → `问题整改台账.xlsx` + 说明。
- 争议事项单独建账（主张 / 审核意见 / 双方依据 / 处理建议 / 状态）：`dispute_register(...)`。

## 十、留痕、保密与脱敏

- 输出门禁每放行/拦截一次都会写入 `references/search/gate_log.jsonl`，可作为过程留痕查阅（`gate.py log`）。
- 被审计单位的合同、结算书、图纸、报价属商业敏感资料：**仅限本次任务使用**，对外举例一律脱敏。
- **附件页码索引**（`04_审计底稿与证据/证据附件页码索引.md`）：报告金额 → 底稿索引 → 附件编号 → 页码 三步可查；页数未定的附件，其后的页码一律留「（待填）」，装订后手工补，**不得跳页累加**；报告附件目录据此自动编号。
- **审计日记与工作记录**（`04_审计底稿与证据/审计日记与工作记录.md`）：按日留痕并挂接底稿索引；结论在底稿、过程在日记，两者须互相印证。
- **电子数据校验值**（`python ingest.py --hash <导出文件>`）：登记导出时间 + 记录数 + 校验值，使用前重算比对；校验值只证明文件未被改动，**不证明数据本身真实**。
- 底稿保存期限按委托方与行业要求执行（⚠️ 具体年限以委托单位制度与最新规定为准）。⚠️ 待核验
