# 08 审计项目档案与成套模板

> 适用角色：审清（主理人）、审计明（造价审计师）、结算清（结算审核师）。
> 本文解决一个问题：**审计的交付不是一份报告，而是一卷档案**——目录固定、命名固定、索引可追溯。

## 一、为什么必须"成套"

- 复核人拿到报告第一件事是问"这个数从哪来"，成套档案让**报告金额 → 底稿索引 → 证据附件**三步可查；
- 委托方、后续审计、纪检或司法调阅时，按同一路径即可取件，不依赖经办人记忆；
- 归档要求本身就是质量要求：**没有归档位置的内容，等于没有做过**。

## 二、固定目录结构（六卷 + 总索引）

| 目录 | 文件 | 用途 |
|---|---|---|
| `00_项目索引.md` | 项目概况、底稿索引规则、文件清单、门禁核验记录 | 档案总入口，复核先看这一份 |
| `01_审前调查与立项/` | 审前调查表、独立性声明与保密承诺、外聘人员与回避记录、审计组分工与联系方式 | 开工前必做，"能不能编实施方案"由它决定 |
| `02_审计实施方案/` | 审计实施方案（目标·范围·方法·进度·分工·检查范围·质量控制）、检查范围与抽样方案 | 本项目的作业纲领 |
| `03_资料索取与交接/` | 资料索取清单（PBC）、资料交接签收单 | 取资料与签收的凭据 |
| `04_审计底稿与证据/` | 审计底稿目录、审计底稿、证据清单与证据链台账、现场取证记录单、抽样见证记录、电子数据取数说明（含校验值登记）、三级复核意见记录表、证据附件页码索引、审计日记与工作记录 | 结论的载体，报告金额的来源与取证过程留痕 |
| `05_问题与争议/` | 问题整改台账、整改回访记录、争议事项台账 | 报告之后的落地与闭环 |
| `06_报告与归档/` | 征求意见与沟通记录、期后事项与追溯调整记录、审计报告（征求意见稿）、卷内目录与归档说明 | 出报告、答复反馈与立卷 |

## 三、索引规则（全档案统一）

- 底稿索引：`W-01`、`W-02`……按审计事项分类，不得跳号、不得一号多项；
- 证据附件：底稿索引 + 顺序号（如 `W-01-1`），可定位到具体文件与页码；
- 台账编号：问题 `I-01`……、争议 `D-01`……，与报告附件目录对应；
- 铁律：**报告里每一项金额都要能指回底稿索引，底稿里每一项金额都要能指回具体证据。**
- 页码：附件页数由 `证据附件清单` 提供，自「附件起始页码」连续累加；**任一项未填页数，其后页码一律留「（待填）」**，装订后手工补填——不跳页累加、不猜数；报告「附件目录」据此自动编号。

## 四、生成方式（一条命令）

```bash
python project_template.py --save-template 项目信息.json         # 1) 导出可填写的项目信息模板（UTF-8）
python project_template.py --meta 项目信息.json --out ./某项目审计档案   # 2) 生成整套档案
python project_template.py --demo --out ./_项目档案示例            # 或用内置示例看结构
```

- 项目信息里填不出来的项，**保留「（待填）」即可**，工具不会编造数据；
- ⚠️ 不要用 PowerShell 的 `>` 去接模板：Windows PowerShell 5.1 的 `>` 会写成 UTF-16 并带 BOM，请用 `--save-template`（工具也能读入 UTF-16，但导出仍以 UTF-8 为准）；
- 补充数据后**重跑同一条命令**即可整体刷新（生成物可覆盖）；
- 检查范围方案由引擎 `sample_plan` 实算（大额必查 + 覆盖率控制，**非统计抽样**）；
- 所有 Markdown 生成后逐份过输出门禁，未放行的文件会在结果里标出并返回非 0 退出码。

## 五、「（待填）」的纪律

- 「（待填）」= **必须由审计人员补充的真实数据**，工具不猜测、不代入经验值；
- 报告/底稿里的数字如果只有条文号而没有数据来源或计算式，会被门禁拦截——这条对生成文件同样生效；
- 待核验的法规事项统一标注 `⚠️`，正式出具前须核对官方原文。

## 六、各卷要点

1. **审前调查**：项目与被审计单位基本情况、审计依据、初步风险判断（量/价/变更签证/调差/程序/资金六类）、资料接收记录、审前结论（可否编制实施方案）。
2. **实施方案**（共十四节）：编制依据（含**合同约定的计价依据版本**）、审计目标、范围与内容、方法与程序（对量 / 勾稽 / 归因 / 偏差调价 / 材料调差 / 资金扣抵 / 指标对标）、检查范围与抽查方案、进度、分工与三级复核、质量控制（数字复算、依据可追溯、单位口径、输出门禁、留痕）、配合事项、交付物清单、计价依据与版本、**重点风险领域与应对措施**（风险导向，具体情形与风险程度由审计人员填写）、**方案调整与报批**（重大调整须重新报批、范围受限须声明）、**编制 / 复核 / 批准签署栏**。
3. **资料与交接**：索取清单须写明形式（原件/复印件盖章/电子）、份数与期限；交接须双方签认，原件核验后退还的在备注注明。
4. **底稿与证据**：九要素齐备；证据分强/中/弱三级；证据链查四点（时间链、主体链、数量链、金额链）；弱证据只能列待核；**电子数据须登记校验值**（导出时间 + 记录数 + 校验值，使用前重算比对）；**审计日记**按日留痕并与底稿索引挂接。
5. **问题与争议**：问题台账到销号闭环（未整改 → 整改中 → 已销号，销号须回访核实并有金额 / 制度 / 程序三类实质证据）；争议台账不影响无争议部分先行结算。
6. **报告与归档**：报告骨架含依据、范围与实施过程、审计发现、处理与整改、征求意见说明、附件目录；卷内目录逐份登记份数与页码。

## 七、复核与门禁

- 三级复核：审计员编制 → 主审复核 → 项目负责人签发，复核意见留痕；
- 交付前：`python content_check.py`（完整性 + 一致性 + 题库复算）、`python project_template.py ...`（生成并门禁自检）、
  `python references/search/gate.py selfcheck <文件>`（末道拦截）。

## 八、归档与保存

- 档案涉商业秘密，查阅须经委托单位批准并登记；对外举例一律脱敏；
- 立卷人、复核人、立卷日期须签署；保管期限以委托单位档案制度与最新规定为准。⚠️ 待核验
